为什么这样设计：第二台机器要跑起来只有两个硬前置——蓝牙能连到板子、有一个能用的转写引擎。语音输入/回读/热键都随 EXE 自带，不需要装任何东西。所以向导就这两步加一次「试说一句」的实机验证：当场看到字上屏，配置才算数。BLE 单连接：板子一次只伺候一台电脑，向导会提醒原机器先断开。
失败回跳：试说一句失败时按原因回到「蓝牙指引」或「转写引擎」，已填内容不丢。跳过向导不阻塞使用——引擎状态条照常报错，顶栏黄条提示补配置，界面里可随时重开向导。
蓝牙适配器缺失/被关向导首步给指引（设备管理器、飞行模式），不阻塞——可以先配引擎，蓝牙好了再连。
扫不到 MicDesktop-*三个原因写明：板子没电 / 被别的电脑连着（BLE 单连接）/ 距离太远；给「重新扫描」按钮。
引擎不可达 / 讯飞凭据错显示具体错误与改法；允许先跳过，主界面里引擎状态条照常报。
试转写失败/超时回对应步骤重试，已填内容不丢；两步都绿了才算配置完成。
边界与约束
  • 不改主流程：向导只写 config.json/state.json，主界面其余功能一行不动。
  • BLE 单连接：向导提示原机器先断开。
  • 凭据不进 git：dist/config.json 已 gitignore，仓库模板保持空。
  • README 同步：补「第二台电脑接入」一节（下载 EXE → 开蓝牙 → 跑向导），与向导步骤一一对应。
