为什么「常开」要靠闸门而不是按键：用户选择的是「说话即输入」，也就是不给人每次确认的机会——那风险就必须由系统兜。三道闸：①短于 0.6 秒的句子直接丢（咳嗽、键盘敲击、椅子响）；②转写结果少于 2 个有效字丢掉（噪声幻觉多是一两个字）；③连续 3 次且间隔 < 2 秒触发刹车暂停（沿用自动回读那套逻辑，实测能挡住自激）。
为什么不用键盘钩子库：keyboard / pynput 装的是全局钩子，安全软件会拦、也会拖慢全系统输入。注入只用 SendInput，热键只用 RegisterHotKey，都是 user32 自带能力，ctypes 直接调，零新依赖。
为什么注入不抢焦点：用户正在微信里打字，这时候程序弹到前面把字打进自己窗口就废了。所以「说话结束时谁在前台，字就进谁」，全程不激活任何窗口。
链路：板子 → BLE → 解码 → 切句 → 转写 → 闸门 → SendInput → 前台窗口光标处。前半段与现有的对话模式完全共用，唯一区别是转写结果的去向：对话模式显示在聊天区，语音输入模式打进别的程序。两种模式可以同时存在——聊天区照常记一份，方便回看。
转写服务不可用本地容器没起或云端不通：状态行报具体原因和命令，这一句不上屏——宁可缺一句，也不要把噪声打进别人的输入框。
常开误触发咳嗽、电视、别人说话被切成句子：0.6 秒 + 2 字 + 刹车三道闸拦；仍挡不住就按 F9 暂停，按钮变黄提示已暂停。
为什么用 BOOT 键：DevKitM-1 只有 BOOT(GPIO0) 和 RST(EN) 两个键，RST 一按就重启，只剩 BOOT 可用。运行期按 BOOT 不会进下载模式——只有复位瞬间按住才会。固件里 20 ms 轮询 + 两次采样去抖，按住 40 ms 才算一次，BLE 未连接时不发（不污染丢包计数）。
前台是终端只按窗口类名判 conhost / Windows Terminal / mintty / PuTTY：默认一个字符都不注入。误识别一句话在终端里就是半条命令。已知局限：VS Code、JetBrains 的内置终端类名与主窗口相同，识别不出来。放行开关：voice_input_allow_console=true 后终端与普通窗口完全一致，文字与「回车」都生效。代价：终端里一句误识别的「回车」会直接执行那行命令。
前台就是本应用说话时焦点在自己窗口：不上屏，只显示在聊天区，避免把字打进自己的输入框。
目标程序权限更高对方是管理员进程（UAC 隔离），SendInput 无效：文字复制到剪贴板并提示，用户手动 Ctrl+V 兜底。
开会 / 不想被输入热键一键暂停，恢复同样一键；暂停时转写照常、聊天区照常记，只是不上屏。
手动点朗读板子开始念：播放期间闸门关闭（等同临时暂停），播完自动恢复，念出来的话不会再被上屏一遍。
边界与约束
  • 不改：板子固件、BLE 链路、解码、切句、转写全部不动；只加「转写结果 → 系统输入」这一段。
  • 零新增依赖：ctypes 调 user32.SendInput / RegisterHotKey，不装 keyboard / pynput 这类全局钩子库。
  • 不抢焦点：注入时不激活任何窗口，目标是说话结束时的前台窗口。
  • 回读互斥：语音输入开启即关闭自动回读，两者不同时生效。
  • 清除只删语音打的字：记账字数 + 记窗口句柄，换过窗口不删；单次上限 4000 字；指令词不参与去重（连说两次「回车」= 两次回车）。
  • 语音指令只认整句：normalize 后等于「回车」或「换行」才按 Enter，「回车键不太好使」照常上屏；不做删除类指令。
  • 不做：标点自动补全、多语言混输、手机端。
已定（2026-10-29）
  • 暂停热键：F9，RegisterHotKey + 自建消息循环，零新增依赖。
  • 启动默认：默认关，开过一次后写入 state.json，下次启动按上次状态恢复。
  • 开关热键：F9 暂停/恢复，Shift+F9 硬开关（同进程注册两个 id，互不影响）。
  • 板载按键：BOOT = GPIO0，短按 = 回车（发 EN 帧，直接按一次回车、不过闸门），长按 3 秒 = 切换语音输入（发 VI 帧，到点即触发）。RST 是 EN 复位脚，不能当输入；J1-10/J1-11（key2/key3，GPIO8/9）仍是空排针。
实测结果
  • 已验证 说话后目标程序出现简体中文、不抢焦点：用户实机测试通过；test_voice_input.py 21/21（真注入 QLineEdit，20 字 / 112 ms）。
  • 已验证 F9 暂停/恢复：打包 EXE 上按 F9，按钮「语音输入 开」→「语音输入 暂停」，状态行同步；日志 热键已注册 vk=0x78，回调延迟 1 ms；热键被占用返回 err=1409 不崩。
  • 已验证 开启后自动回读关闭；回读播放期间的那句话不上屏。
  • 已验证 状态持久化：state.json 原子写，重启后与上次一致。
  • 已验证-否 一次 SendInput 批量送多字不可靠：16 字一批时目标窗口只认每批首字（读回「你你你你…6666」），type_text 固定逐字送。
  • 已验证（单测） 终端护栏与回车指令：risky 分支、类名判定、注入后末尾多一个换行，共 30/30。
  • 已验证 F9 与 Shift+F9 同进程注册各命中一次；错误文字不再走 on_result（讯飞失败路径改报丢弃，否则会被当人话打出去）。
  • 已验证 转写失败/空结果会报 on_drop，时长队列不再错位。
  • 已验证（单测 37/37） 回车词表补近音：实测 whisper 把「回车」听成「回出」两次，收 回车/换行/回出/回撤/回扯/回彻/会车，并支持 config 里的 voice_input_enter_words 自定义。
  • 已验证（单测 37/37） 终端放行开关：类名判定命中时不注入；放行后文字照打、「回车」同样按一次 Enter（首版曾禁用终端回车，按用户要求取消）。
  • 已验证 误拦根因：日志 risky target cls='CASCADIA_HOSTING_WINDOW_CLASS'；另一处误拦来自「标题含管理员」的普通窗口，已删除该规则。
  • 已验证（端到端） 实按 BOOT：板子发 VI 帧，PC 端收到 voice_toggle，链路通。
  • 已验证（硬件） BOOT 键=GPIO0：GPIO? 探测 16 Hz 采样，第 5.3 秒 GPIO0 变 0，其余 13 脚不变；PC 端解析 VI 帧的单测通过，STAT 新增 key=N 计数。
  • 部分验证 环境音误触发：闸门单测覆盖 too_short / too_few / brake，真实环境误触发率待长时间使用观察。
