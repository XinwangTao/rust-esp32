自动回读只挂在 on_result 一个入口上，手动「朗读」按钮的路径一个字不动——两条路互不影响。
正在播报时又来了新结果：不打断当前播放，排队最多 1 条，再多的直接丢最新的（宁可少念，不可积压成延迟）。
去重键是归一化后的文本（去空白/标点），与最近 5 条已念文本比对：AEC 残留把刚念的话又转写回来时，靠这一步挡住自激。
回环：转写 → 闸门 → 念 → 被麦克风收回去 → 又转写。AEC 把回声压到环境底噪附近（实测播放期间平均 RMS 97 vs 底噪 104，VAD 阈值 350），正常不会成环；去重 + 刹车是防它万一成环的两道保险。
板子不在线没有可用 IP（没收到过上行包且 config 也没写 board_ip）：跳过本句，界面提示「未回读：板子不在线」，不影响转写与落盘。
自激循环念出去又被转写回来：先靠文本去重挡住；仍连续触发则刹车暂停并提示「回读已暂停，疑似自激」，需手动恢复或关掉开关。
合成失败SAPI 报错：跳过这一句，只记日志，不影响下一条，也不重试（避免卡在坏句上）。
噪声误转写被念出来环境噪声或短促声响被判成文字：少于 2 个有效字符不回读；仍频繁出现就把 auto_speak 关掉或先上设备端降噪。
说话被打断的错觉半双工（板子没 AEC）时朗读期间麦克风是静的：你说话会被丢弃，不会被转写——这是既有行为，图不变，界面已有「模式 半双工」提示。
边界与约束
  • 改动范围：main.py 的 on_result 接一条回读支路 + 新增 micapp/readback.py + config 加 auto_speak；固件与 UDP 协议零改动。
  • 只处理「STT 出结果」这一条触发源，不做「检测到说话即回读」（那需要额外的 VAD 钩子，本轮不做）。
  • 手动「朗读」按钮、转写气泡、转写落盘全部保持原样。
  • 默认关闭：自动回读会把误转写也念出来，风险比手动大，必须由人显式打开。
  • 不做：变声/多音色、按句长截断、情绪与语速调节、回读历史记录。

  • 朗读中来了新句子：排队最多 1 条，超出丢最新的。
  • 刹车阈值：连续 3 次且间隔 < 2 s，实测再调。
