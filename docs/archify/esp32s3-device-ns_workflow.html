NS 就地处理：进来 320 个采样、出去还是 320 个，不引入额外延迟；但库只吃 10 ms 帧，所以内部拆成两个 160 采样子帧跑（esp_ns.h 注释写“支持 10/20/30”，2.4.7 实现在 esp_ns.c:29 断言 frame_length_ms==10，传 20 会直接 panic 重启——此坑已实测踩过）。
顺序固定 AEC → NS：AEC 需要原始 mic 与 ref 做自适应，降噪放在它后面，否则会把 AEC 的参考路径也改掉。
输出缓冲 320 字节走内部 RAM，不新增内存池。
回环：采集 → AEC → NS → 上行 每 20 ms 走一圈；NS 每帧 320 采样，耗时会计入 STAT 的 ns_us_avg，与已有的 us_avg（AEC）分开记，便于分别归因。
ns_create 返回 NULL打日志 + STAT 报 ns=off，上行保持 AEC 输出（直通），链路不中断，与当初 AEC 初始化失败的兜底一致。
抑制过头伤语音近讲时声音发闷、转写开始丢字：换 ns_pro_create(10, 0, 16000) 温和档（10 ms 子帧，mode 0），仍不行就整段关掉。
CPU 超预算AEC 已占 29%（峰值 36%），叠加后若采集线程停顿导致包率掉出 50 pkt/s：先关 NS 回退，再考虑降 AEC 档位。
噪声类型不对远处人声 / 电视 / 多人说话属于人声干扰，降噪算法基本无效：不在本轮范围，不做承诺，需要靠 VAD 分段另解。
降噪后音量变小NS 会连带压低底噪，VAD 阈值 350 在高噪环境可能仍偏高：只用 STAT 指标确认后再决定是否调阈值，本轮不动 VAD。

边界与约束
  • 改动范围：固件 audio_transmitter.cc 在 audio_aec_filter() 之后加一行 audio_ns_process()，新增 audio_ns.cc/.h，audio_speaker.cc 的 STAT 回包加字段。mic-desktop 一行不动。
  • 上行仍是 20 B 头 + 320 采样 s16LE / 50 pkt/s，PC 端不升级也能收。
  • NS 不引入额外延迟（原地 320 采样）；端到端延迟保持 AEC 那 32 ms。
  • 只处理稳态环境噪声；人声干扰、混响、啸叫不在本轮。
  • 不做运行期开关、不做自适应强度；初始化失败即直通。
  • VAD 阈值本轮不动，先看降噪后指标再决定。

已决问题（用户确认 2026-10-29）
  • 档位：标准档（ns_create，非 ns_pro_create）。
  • 运行期开关：不做，STAT 观测 + 重新烧录回退。
  • CPU 通过线：AEC+NS 合计 avg ≤ 45% / peak ≤ 60%，且 50 pkt/s 丢包 0。当前 avg 41.4% 达标，peak 口径待补。
