为什么这样设计：板子蓝牙是单连接，两台同时做不到，用户要的是「快速切换打进哪台」。中枢把转写好的文字（含时长）按当前目标分流——本机直接走现有 voice_input 上屏，第二台经局域网 HTTP 发给轻量接收端，接收端复用同一套 voice_input 闸门与注入。只转文字：第二台不需要转写引擎、不需要蓝牙，装个小接收端就行。
分流在 main.py 的 on_result 里做，采集/切句/转写/板子固件一行不改。第二台接收端只起一个 HTTP 端点 + 复用 voice_input.py/typer.py，不连板子、不跑 STT。
第二台不可达 / 超时文字回本机上屏 + 状态行提示「第二台不可达，已回本机」，不丢字。
第二台前台是终端/管理员沿用现有护栏：不上屏，状态提示（与 voice-typing 一致）。
切换热键被占用状态行提示注册失败，语音输入照常，可改键位。
边界与约束
  • 中枢改动最小：只在 on_result 按目标分流；采集、切句、转写、板子固件不动。
  • 第二台轻量：一个 HTTP 端点 + 复用 voice_input/typer，不连板子、不跑 STT。
  • 只转文字：第二台无需转写引擎与蓝牙。
  • 传输：同局域网 HTTP POST JSON，端口独立（建议 8391，避开 whisper 8390）。
  • 状态：目标记 state.json，重启恢复；热键与 F9/Shift+F9 不冲突。
