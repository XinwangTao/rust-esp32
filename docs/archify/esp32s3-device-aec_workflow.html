回环：重分块 同时承担「320 → 512」和「512 → 320」两个方向，8 个 320 帧正好拼 5 个 512 帧。
回环：capture → reblock → aec → reblock → uplink 每 32 ms 走一圈；ref 由播放线程异步填充，AEC 内部自适应对齐延迟。
组件拿不到/不兼容esp-sr 拉不下来或与 IDF 5.3.1 冲突：放弃设备端 AEC，保留现行 PC 侧 MicGate，理由写进调研文档。
PSRAM 分配失败aec_create 返回 NULL：直通（mic 原样上行），只告警，协议与 PC 侧都不变。
CPU 不够I2S 读超时或包率掉到 50 以下：降档 SR_LOW_COST（18.8 KB 内部 RAM / 64 KB PSRAM）；仍不够回退直通。
ref/mic 时延抖动大回声消不干净：不执行 pcswitch，MicGate 继续兜底（半双工仍可用）。
撤销门控后变差出现回采重复或用户语音被削：恢复 mic_mute_tail_s，门控与 AEC 并存，调 NLP 档位再验。

边界与约束
  • 改动范围：固件采集→上行链路（新增 AEC 段）+ mic-desktop 的 mic_mute_tail_s 默认值；AUD0 帧格式、5000/5001 端口语义都不动。
  • 上行仍是 20 B 头 + 320 采样 s16LE，PC 端**不升级也能收**。
  • AEC 以 32 ms 为处理块，上行端到端延迟预计 +32–64 ms（需实测确认）。
  • 体积：当前 app 1.1 MB，esp-sr + esp-dl 预计 +1–2 MB；factory 分区 4 MB，够但需复核。
  • 本轮只上 AEC 单个变量：不接唤醒词/ASR 模型，不接 NS 降噪，不改编码。
  • 始终保留直通开关（初始化失败即直通）与 PC 侧门控回退。
