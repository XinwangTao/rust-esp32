# 跨机语音输入（热键切换打进哪台）— 需求简报

> L2 · 新子系统 · 状态：问清完成，待图确认

## 用户与问题
- 用户：一个用户、一个无线麦板子（ESP32-S3 + INMP441）、两台**同一局域网**的 Windows 台式机。
- 问题：想把语音输入（说话即打字）用起来，并能**快速在两台电脑之间切换「这一句打进哪台」**。
- 明确不做：**两台同时**（最初提过，已否掉）；手机端；音频转发（只转文字）。

## In / Out of Scope
- In：
  - 这台电脑（板子当前连的）当「转写 + 转发」中枢。
  - 中枢转写好文字后按当前目标分流：本机 → 本机上屏；第二台 → 经局域网把文字发给第二台，第二台上屏。
  - 全局热键一键切换目标（本机 ↔ 第二台）。
  - 第二台装一个轻量「收文字上屏」接收端。
- Out：板子固件改动、两台同时、第二台独立转写、跨网段/公网、手机端。

## 成功标准（可验收）
1. 中枢说一句、目标=本机：本机前台出字（回归现有功能不破坏）。
2. 按一次热键切到「第二台」，再说一句：第二台前台出字，本机不出。
3. 第二台不可达时：文字回本机上屏并给状态提示，不丢字。
4. 热键来回切，目标状态可见、持久化（重启恢复）。

## 主路径场景
- 说话 → 中枢切句转写 → 判断目标 → 本机 / 第二台上屏。
- 关键失败/兜底：第二台不可达 → 回本机 + 提示；第二台前台是终端/管理员 → 沿用现有护栏不上屏。

## 关键约束
- 同局域网；中枢与第二台之间走 HTTP POST JSON（端口避开 whisper 的 8390，建议 8391）。
- 转发文字（非音频），第二台无需 STT 引擎、无需蓝牙。
- 复用现有 `voice_input.py` / `typer.py` 的注入与护栏，不重造。
- 切换热键不与已有 F9 / Shift+F9 冲突。

## 待确认（见图）
1. 转发失败兜底：第二台不可达时「文字回本机 + 状态提示」，是否接受。
2. 切换热键具体键位（建议 F8 或 Shift+F8）。
3. 第二台是否沿用本机同套护栏（终端不注入、回车/清除指令、去重）。

## 借鉴调研（弱）
- 同类：KDE Connect / Barrier / Synergy（局域网输入/剪贴板共享）、Pushbullet（跨设备剪贴板）。结论：单向文字跨机转发是成熟低风险模式，无重活。
- 影响：① 单向文字用无状态 HTTP POST 即可，不必维护长连接；② 注入复用本仓库 typer.py 的「剪贴板 + Ctrl+V」（已有 IME 兼容结论），不必另造。
